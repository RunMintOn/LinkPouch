# 收藏内容墙与站内预览

适用：修改收藏页视觉结构、瀑布流间距、卡片内容或右侧预览。

## 决策入口

先读 [ADR-0001](../adr/0001-local-content-collection.md) 的“以识别辅助找回”和“先在收藏内预览”。实现入口是 `src/queue/main.tsx` 与 `src/queue/queue.css`，用户操作见 `README.md`，这里仅保留代码不直接体现的取舍与实验。

- 用户选中真实收藏原型的 B「视觉墙」作为默认方向。图文混排，不为纯文字收藏强造封面或网页截图。
- 旧备注可能兼作正文摘录。不能用备注长度直接推断用户意图，也不能把高频词当成稳定分类；本次没有更换快捷备注、统一历史用词或添加语义检索。
- 首屏有图不代表全库有图。判断布局时同时看更早的纯文字收藏；缺失提示留在详情，不在每张卡片重复展示。
- 收藏卡片的远程配图不等于 Gallery 的本地图片文件。缩略图持久缓存、网页截图和旧网页自动补采均不属于当前浏览界面。

## 瀑布流间距：已验证的坑

旧方案用 `8px` 网格行加 `16px row-gap`，按 `24px` 步长向上取整卡片占位。多出的占位落到卡片下面，导致同一列上下间隙不同；图片高度不同不是间距必须不同的理由。

修正为像素级网格行，卡片下方间距计入自身占位，纵向网格 gap 为零；横向 gap 独立。`ResizeObserver` 随图片加载、内容变化和窗口换列更新占位。这两部分必须一起调整，不能仅减小行高却保留每行的 gap。

在独立、离线的扩展 profile 中使用 333 条收藏副本测得：

| 视口宽度 | 修正前上下间隙 | 修正后上下间隙 |
| --- | --- | --- |
| 1440px | 17–38.98px | 16–16.98px |
| 850px | 17–35.88px | 16–16.91px |

剩余不足 1px 为向上取整误差，不要再次承诺“数学上完全相等”。未来若改卡片外边框或 padding，测量高度和占位高度需保持同一盒模型。

## 最小验证路径

- 只修布局时，在独立 Playwright context 中加载构建后的扩展与本地收藏副本，设 `offline: true`。无需访问真实 X，也不连接用户日常浏览器。
- 等字体和可见图片加载结束、`ResizeObserver` 完成布局后，按 `.card-grid` 内卡片的 `getBoundingClientRect().left` 分列，计算相邻卡片的 `next.top - previous.bottom`；看数值和截图，不只看 CSS 的 gap。
- 检查正常宽度和窄窗口即可；不要为间距改动重复跑全文采集、目录授权或真实账号流程。
- 涉及交互时复用 `scripts/smoke-extension.mjs` 的正文搜索及预览场景：打开预览不新增标签、不改变卡片边界；Escape 关闭后搜索词仍在。该脚本使用模拟站点，证据边界见[采集文档](content-capture.md)。

## 原型归档

本地分支 `prototype/collection-wall` 保存 `src/queue/prototype.html` 和 `src/queue/prototype.mjs`，可切换 A 混合卡片、B 视觉墙、C 紧凑索引。它只用于比较结构，默认分支不保留原型代码。

在该分支的独立 worktree 中运行 `node src/queue/prototype.mjs /absolute/path/to/backup.json`。需自行提供当前备份；原型未内嵌个人收藏。原型会按需请求备份中的远程图片，不应当作离线验证工具。
